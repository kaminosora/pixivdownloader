## 帧率与时序证据

Pixiv ugoira 使用每帧 `delay`（整数毫秒），不假定一个固定 FPS。视频测试输入 `[7,13,1001,60000]`，得到时间戳 `[0,7,20,1021]` 毫秒、逐帧时长与输入完全相同，总时长 61.021 秒；包含最后 60 秒的停留。单帧 1234 毫秒、四帧各 40 毫秒也通过。

MP4 的 `mdhd/stts` 由测试独立解析，时基为 1000，逐帧 duration 与输入整数毫秒相等，避免仅用封装库自己的解封装器得出结论。VP9/VP8 使用真实编码器，测试只在能力查询边界过滤前置编码器，以覆盖备选格式。所有格式均解码全部帧并加载 HTML video，没有固定 25/30/60 FPS 重采样。播放器的平均 FPS 显示可能不同于某一帧间隔。

Mediabunny 1.64.0 原版 movie header 使用 57600 时基，MP4 容器总时长字段可能有不超过约 8.7 微秒的舍入；视频轨道每帧和末帧的毫秒时序精确保留。运行时未修改库源码；对应源码和许可证随发布包提供。

尺寸验证：63×35 在 MP4 补到 64×36，原内容不拉伸；2400×1600 缩为 1920×1280；不放大小图。视频无音轨，透明区域黑底。视频是有损转换，播放循环由播放器设置决定。

扩展端到端样例使用 `[7,13,1001,660000]` 触发 GIF 时序上限，输出一个来源名称的视频，总时长 661.021 秒；没有按真实时长等待或录屏。

## 限制与资源验证

- GIF：600 帧、最长边 1280、缩放后累计 150M 像素、原帧累计 128 MiB、编码输出 128 MiB、GIF 单帧时序表达范围。只有这些结构化容量限制触发视频。
- 视频：最长边 1920；编码数据及最终文件最多 256 MiB；单个原始图片仍最多 128 MiB。累计原帧可超过 GIF 限制，因为视频逐帧消费；中途切换会先消费并释放已下载缓存。
- 单元边界测试覆盖 GIF 输出超限、视频输出超限和累计 131 MiB 原帧逻辑输入。为避免无意义内存压力，部分边界使用受控数据/编码器替身；没有测量接近上限时真实浏览器的内存峰值。字节上限不代表浏览器进程总内存上限，解码、画布与封装会另占内存。
- 损坏图片、原帧尺寸不一致、网络错误和权限失败保持失败，不伪装成视频成功。取消后停止索取后续帧，关闭位图、VideoFrame 和编码器。修复了编码器同步 error 回调与 rejected flush 同时发生时的未处理 Promise 拒绝。
- 最初 bundled Chromium 141 缺少 H.264 解码器，视频测试遇到平台解码限制；改用本机 Google Chrome 156 的独立项目内配置完成全部 H.264/VP9/VP8 验证。测试不读取日常 Chrome 配置或登录资料。可用 `PIXIV_TEST_BROWSER` 指定 Chrome 可执行文件。

## 目录测试范围

扩展测试唯一目录选择边界替身是 `showDirectoryPicker` 返回真实 OPFS DirectoryHandle；其后真实 IndexedDB 句柄传递、创建/写入/读回、权限查询、冲突文件名和后台处理均参与。没有模拟生产函数或 chrome.runtime。

此前 1.1.0 在隔离的有界面 Chromium 中实际调用了系统文件夹选择器，但原生控制工具无法绑定窗口：`window id 4133858 no longer belongs to Chrome; current owner is Chrome`。系统选择未完成，三分钟上限后测试浏览器退出，没有操作日常 Chrome。证据保留在 `verification-native-picker.json`。

因此**没有验证外部硬盘文件夹的实际授权、关闭授权页后的权限寿命**；OPFS 不代替该验收。本次没有重复这项已有环境障碍测试。下载期间仍需保留文件夹设置页，权限失效时重新选择授权。

## 使用环境验收

1. 加载或更新到 1.2.0，重新加载扩展，刷新已有 Pixiv 页，选目录并允许写入。
2. 静态单图、多图均落在所选目录顶层，字节/格式不转换，文件名与原图 URL basename 相同。
3. 普通动图只保存 `_ugoira.gif`；超限动图只保存 `_ugoira.mp4` 或 `_ugoira.webm`，图像顺序、节奏与 Pixiv 一致。
4. 同名不覆盖，新副本加 (1)；不会逐文件弹出另存为。完成结果和实际文件名见扩展面板，Chrome 下载列表没有记录属于直接写目录的预期。
5. 另一个 Chrome 窗口的作品不进入本窗口下载任务；推荐链接不进入任务。

真实 Pixiv 登录账户、风控、地域网络与未来接口变化未做端到端自动验收。用户提供作品 121113419 的登录态原图仍需使用环境验收；旧哈希路径兼容证据保留在 `verification-hash-fix.json`。历史来源头网络测试为 1.0.0 的 `verification-network.json`，DNR 未改变，本次未重复两个独立网络测试。
